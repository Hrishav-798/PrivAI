Horizontal Pod Autoscaling (HPA)

kubernetes.io — Official Documentation

Overview

In Kubernetes, a HorizontalPodAutoscaler automatically updates a workload resource (such as a Deployment or StatefulSet) with the aim of automatically scaling the workload to match demand.

Horizontal scaling means that the response to increased load is to deploy more Pods. This is different from vertical scaling, which means increasing the resources (CPU or memory) assigned to existing Pods.

If the load decreases, and the number of Pods is above the configured minimum, the HorizontalPodAutoscaler instructs the workload resource to scale back down.

How does an HPA work?

The HPA is implemented as a Kubernetes API resource and a controller. The resource determines the behavior of the controller. The horizontal pod autoscaling controller, running within the Kubernetes control plane, periodically adjusts the desired scale of its target to match observed metrics such as average CPU utilization, average memory utilization, or any other custom metric you specify.

Algorithm Details

The HPA controller calculates the desired number of replicas using the formula: 

desiredReplicas = ceil[currentReplicas * (currentMetricValue / desiredMetricValue)]

Example HPA Configuration

apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: my-app-hpa
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: my-app
  minReplicas: 2
  maxReplicas: 10
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 50
  - type: Resource
    resource:
      name: memory
      target:
        type: Utilization
        averageUtilization: 70

Supported Metric Types

  • Resource metrics — CPU and memory utilization of Pods
  • Custom metrics — Application-specific metrics (e.g., requests per second)
  • External metrics — Metrics from outside the cluster (e.g., queue length)
  • Object metrics — Metrics from other Kubernetes objects

Scaling Behavior

You can configure scaling policies that control how fast the HPA scales up or down. The behavior field allows you to set stabilization windows and rate limits: 

behavior:
  scaleDown:
    stabilizationWindowSeconds: 300
    policies:
    - type: Percent
      value: 10
      periodSeconds: 60
  scaleUp:
    stabilizationWindowSeconds: 0
    policies:
    - type: Percent
      value: 100
      periodSeconds: 15
    - type: Pods
      value: 4
      periodSeconds: 15
    selectPolicy: Max

Best Practices

  1. Always set minReplicas to at least 2 for production workloads
  2. Use resource requests on all Pods for accurate CPU-based scaling
  3. Consider using custom metrics for more precise scaling decisions
  4. Set appropriate stabilization windows to prevent flapping
  5. Monitor HPA events to understand scaling decisions
  6. Test scaling behavior under load before going to production

Useful Commands

# Create an HPA
kubectl autoscale deployment my-app --cpu-percent=50 --min=2 --max=10

# Check HPA status
kubectl get hpa

# Describe HPA details
kubectl describe hpa my-app-hpa

# Watch HPA in action
kubectl get hpa --watch
